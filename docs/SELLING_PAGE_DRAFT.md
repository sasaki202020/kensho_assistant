# 販売ページ草案

## 商品の特徴

- 懸賞生活を入口に懸賞情報を整理
- 応募条件と危険案件をルールベースで分類
- 応募条件を見える化
- 危険な案件を除外
- フォーム入力を補助
- 応募履歴を管理
- profile はローカル暗号化に対応
- 自動スキャンで候補の収集・分類・診断をまとめて実行
- 人間確認モードで候補を見て判断
- スクリーンショット保存は既定OFF
- 個人情報はローカル暗号化
- `v0.2-beta-final` として配布しやすい CLI + GUI 構成

## できること

- 懸賞情報の収集
- 応募タイプの分類
- 危険案件の除外
- 応募済み管理
- フォーム入力補助
- `REVIEW_ONLY` の手動確認ポイント表示
- 応募履歴とレポート出力
- 自動スキャン
- 人間確認モード

## できないこと

- 当選保証
- 完全自動応募
- CAPTCHA突破
- SNS自動フォロー/いいね/リポスト
- ログイン回避
- 規約違反の応募
- 懸賞生活の公式サービス代替
- 同意チェックボックスの自動チェック
- 年齢の自動入力
- メルマガ自動登録
- v0.2-beta-final での本番送信推奨
- 自動スキャンでは個人情報を使わない

理由:

- 個人向け懸賞ツールはサブスク継続が難しい
- note / Gumroad / BOOTH で売りやすい
- ユーザーの個人情報をサーバーで預からない設計と相性がよい
- 懸賞専用メールの運用と相性がよい

## 注意事項

- 懸賞生活の公式ツールではありません
- 応募はユーザー本人の責任で行ってください
- キャンペーン規約の確認は必須です
- 当選保証はしません
- 同意チェックは自動化しません
- 暗号鍵をなくすと profile は復元できません
- 自動スキャンでは個人情報を使いません
- 応募送信の自動化はしません

## よくある質問

- 完全自動で応募できますか？
  - いいえ。送信前にユーザー承認を挟みます。
- X懸賞にも使えますか？
  - 初期版は対象外です。
- 個人情報はどこに保存されますか？
  - ローカルの `profile.enc` に暗号化保存します。
- profile は暗号化できますか？
  - はい。`profile.enc` を使えます。
- 同意チェックは自動ですか？
  - いいえ。ユーザー確認が必要です。
- REVIEW_ONLY とは何ですか？
  - 年齢や同意など人間判断が必要な案件を安全側で分けるモードです。
- 当選率は上がりますか？
  - 保証しません。管理と確認を助けるツールです。
